# Profiling and inference organs: proposed read contracts

**Design proposal — 2026-10-01, [Brain #444](https://github.com/PyAutoLabs/PyAutoBrain/issues/444).**
This specifies two future cross-project dashboards. It does not create organs,
change producer schemas, migrate artifacts or introduce new agent commands.
The descriptive names **profiling organ** and **inference organ** are placeholders;
repository names remain a human choice at implementation time.

## Decision

Use two domain-specific organs, each with an instance registry and a versioned
read contract. Many profiling projects can feed the profiling organ; many inference
projects can feed the inference organ. Keep domain producers and measurement
semantics in their project repositories. An organ owns the cross-project view,
registry and ingestion diagnostics; the Brain and human own interpretation and
next-action decisions. This follows the [adopted responsibility roles][roles] and
[Eyes' project/organ/conductor separation][eyes].

A dashboard alone does not make a repository an organ. The proposed organ's
additional responsibility is maintaining a reliable view across independently
owned projects. Start with the existing lens project and a second real producer
before declaring the cross-project rollout complete. A second-project fixture can
test the reader early; it cannot substitute for a real adopter. Do not manufacture
empty sibling repositories just to satisfy that milestone.

The [routing trial](ecosystem_routing_trial.md) does not justify adding a mandatory
checklist or one agent per role. Existing conductors remain the action doors. The
original three roles describe responsibilities, not a containment hierarchy:
a project may supply several organs, and an organ may read many projects and
libraries. Repository category and release mechanics remain unchanged.

## Ownership and existing starting points

| Responsibility | Profiling | Inference |
|---|---|---|
| Produce measurements | Each `*_profiling` project | Each `*_inference` project |
| Own raw artifacts and domain summaries | Project, including provenance and pins | Project, including retained samples and convergence diagnostics |
| Own cross-project registration and display | Proposed profiling organ | Proposed inference organ |
| Judge an observation | Brain profiling conductor with human | Human scientist through the Cortex check-in; samplers faculty may advise |
| Record development work | Mind, via intake/bug/start_dev | Mind, via intake/bug/start_dev |
| Record scientific observations and lessons | Cortex on the human's instruction | Cortex on the human's instruction |
| Issue release-health verdict | Heart | Heart |
| Run packaging/release mechanics | Hands through existing workflow | Hands through existing workflow |

The [profiling producer][profiling-dashboard] already writes
`dashboard/series.json`, `dashboard/state.json` and `dashboard/index.html`. Its
series describe release trends; qualification and drift are project rules. Its
runtime badge uses a 2x ratio and 1 ms floor, distinct from the compile conductor's
1 s floor. Preserve that distinction and expose the source policy; do not impose
one threshold across axes or projects.

The [inference renderer][inference-renderer] reads project result JSON and builds
README tables. It handles multi-stage payloads and parity groups; that is not yet
a declared cross-project exchange contract. [Inference instructions][inference]
keep large samples/output outside git and commit small result rows. An organ
links to available evidence instead of copying posterior output into its own repo.
Do not revive or cite the retired inference programme as evidence for this design.

The inference instructions still contain older Cortex task/ruling wording.
For this specification the [current Cortex contract][cortex] is authoritative:
project ledgers have Now, Runs and Log; they are not a second development queue.
The separately filed documentation reconciliation remains separate work.

## Two interfaces, with different consumers

**Project → organ:** a proposed versioned, domain-specific summary, generated by
the project from its own artifacts. Its path is registered explicitly; no producer
must adopt a guessed conventional filename. Project implementations adapt their
existing formats once. The organ does not scan arbitrary result trees, import
scientific libraries or reconstruct scientific meaning from filenames.

**Organ → Brain board:** the existing [cockpit state contract][board], with the
organ's identity and links to the detailed cross-project dashboard. Its `updated`
is the render time, and `valid_until` is an optional producer-declared deadline;
a fresh render must not imply fresh measurements. The domain summary below is
not a replacement for `state.json` and must not be validated as that schema.

The existing profiling project feed happens to use `organ: profiling`. That
legacy wire label is not proof that the project is already an organ. During
transition keep the project page/feed working. When a real organ is registered,
update the Brain board's source and identity in the same rollout step, retaining
a clear link to the project page and avoiding duplicate cards for the same scope.
Do not silently repoint a feed before the new consumer contract is tested.

## Proposed project registry

Each organ owns a registry with a version and one row per instance:

| Proposed field | Meaning |
|---|---|
| `instance` | Stable key within the organ; unique and independent of display name |
| `repo` | Existing Mind body-map repository identity |
| `summary_path` | Repository-relative path of the producer's declared summary |
| `supported_schema` | Domain contract/version the reader expects |
| `dashboard_url` | Human-facing project view |
| `library_refs` | Zero or more body-map identities exercised by this project |
| `cortex_project` | Optional existing Cortex key, not a copied ledger |

Resolve repository location and GitHub identity through the body map; do not
create a second authoritative repository catalogue. Resolve the selected branch
to one commit for each ingest and read all that instance's files at that commit.
Store the resolved commit in the organ's derived receipt. An explicitly requested
local read reports its checkout revision and dirty state and cannot masquerade as
a published snapshot. No hard-coded local absolute paths belong in the registry.

One project may have several declared scopes, but identity must remain explicit
and disjoint. Do not register the same summary twice under different names to
inflate coverage. Adding a producer requires a validated fixture and documented
ownership; discovery by a `*_profiling` or `*_inference` name alone is insufficient.

## Proposed summary envelope

These fields are a **new proposal**, not claims about current producer files.
Use separate domain schemas (`profiling-summary` and `inference-summary`) with
an integer version and a small common envelope:

| Field | Requirement |
|---|---|
| `schema`, `version` | Known domain and supported integer contract version |
| `project`, `scope` | Match the registry and declare what this feed covers |
| `generated_at` | UTC summary generation time |
| `evidence_updated_at` | Latest included measurement timestamp, or null with reason |
| `valid_until` | Optional declared freshness deadline; absence means unspecified |
| `producer_revision` | Commit of the producer code used to generate this summary |
| `coverage` | Declared expected cells/runs where known, observed counts and exclusions |
| `records` | Stable record IDs, provenance, domain fields and evidence links |
| `limitations` | Explicit missing provenance, diagnostics or coverage constraints |

The ingestion commit is recorded by the reader, separately from producer code
revision and measured library revisions. This avoids a generated file trying to
contain the hash of the commit that will first contain it. Record library/package
versions and revisions when known; do not infer them from the current checkout.

Evidence links resolve against the captured repository commit or an explicitly
identified immutable artifact. Carry a digest when the artifact format provides
one. Link lifetime or access restrictions must be visible; a missing remote sample
archive does not erase the small result row. Public dashboards must not expose
private storage paths, credentials or raw private science payloads.

Reject unsupported versions, duplicate IDs, invalid dates, unsafe relative paths
and non-finite numeric metrics. Required missing fields make a feed invalid.
Optional unknown values use null plus a reason, never zero or a success default.
Ignore additive fields that do not change existing semantics. Breaking changes
require reader support first, then producer migration; preserve old-version support
through the declared transition. The organ validates the exchange contract, while
the project validates its domain semantics.

## Profiling domain contract

A record identifies the measurement axis (runtime, compile, breakdown or memory),
workload/cell, dataset/model/instrument or component identity, backend/device,
precision, implementation variant, dependency versions, timing protocol and units.
Keep warm-up/cache/load provenance and repeat counts when measured; mark gaps.
A memory value cannot enter a seconds series, and a component timing cannot be
presented as a full likelihood cost.

For comparisons, require the producer's explicit comparison key, policy identifier,
baseline reference and reasons for qualification or refusal. Distinguish release
trend display from evidence sufficient to declare regression. Library revision
may intentionally vary in a release comparison; the policy must name that axis
and the controls that must match. A config label alone is not comparability proof.
Missing controls permit a contextual plot with warnings, not an unqualified ratio
or winner badge. Historical trends may remain useful without being comparable.

The organ displays project-supplied drift candidates and provenance. It does not
move pins, combine unmatched timings, apply the compile threshold to runtime,
compute an ecosystem-wide speed score or issue a Heart verdict. A drift item links
to its pair of records and offers the existing profiling triage door. A confirmed
library defect subsequently takes the normal Mind development route.

## Inference domain contract

A record identifies target, dataset/model/pipeline variant, sampler/configuration,
backend/device, precision, seed and stage or whole-run scope. Preserve parent-run
identity for a multi-stage pipeline. Record execution status separately from
scientific acceptance: a completed process is not proof of convergence.

Report setup, sampling and total wall time with explicit definitions, including
whether compile, resume or parallel work is included. Unknown setup cost remains
unknown; overlapping stage durations must not be blindly summed into a total.
Retain links to samples, diagnostic histories and raw result rows, with availability
status. Include diagnostic names/values when provided and an explicit `not_assessed`
state when they are absent. No universal convergence threshold is introduced here.

Preserve the project's parity identity and seed grouping. Compare cost only among
compatible targets and execution definitions; compare scientific quality only
under a declared project protocol, retaining failed and stopped runs as visible
coverage rather than removing them from the denominator. Do not rank samplers by
fastest wall time across different models or silently select the best seed.

The organ can display “diagnostics missing”, “run stopped” or “human interpretation
linked”. It cannot promote a default sampler, infer a lesson or turn missing
posterior evidence into success. Human conclusions link to Cortex's existing
record instead of being independently editable dashboard verdicts. Science follow-up
uses Cortex; a summary-script defect uses bug/intake/start_dev; the read-only
samplers faculty provides optional context. No inference conductor is invented.

## Dashboard, failure handling and action boundaries

The first page shows one row per registered project with scope, evidence time,
last fetch, coverage and links. Domain detail pages retain project identity and
allow comparable groups to be inspected. Avoid a global league table across
unrelated scientific tasks. Show missing and refused evidence alongside valid data.

Keep three distinct notions visible: transport/schema integrity, evidence freshness,
and scientific qualification. A valid empty feed says “no measurements”; it is not
“all measurements passed”. Partial ingestion must report which instances failed.
The organ can retain the last successful snapshot, but label it cached, retain its
original evidence timestamp and show the new fetch error. Never refresh a cached
record's age by rerendering the page.

An explicit expired deadline makes evidence stale. Without a declared age policy,
show the age and “freshness policy unspecified”; do not invent a global TTL. Healthy
transport cannot make unknown scientific quality green. Cockpit status summarizes
the organ's own monitoring scope, with reasons and coverage, not ecosystem release
readiness. Feed failures and stale evidence must remain visible even if some
projects report more urgent domain findings; every summary links to the full list.

Action chips use the existing board's action descriptors and safety metadata.
A link opens evidence; a prompt proposes a manual handoff. Fetching/rendering never
submits jobs, re-pins a baseline, logs a lesson, edits source or grants approval.
Actions retain the project key and evidence revision so an agent can read the
relevant project and contract without loading every repository.

## Implementation sequence and acceptance

1. **Publish one project contract per domain.** Add small project-owned exporters
   over existing results, fixtures and schema checks. For profiling adapt the
   current series output without changing historical results or drift policy.
   For inference retain pipeline/seed identity and unavailable sample links.
   Resolve the existing inference worktree claim before editing that repository.
2. **Build organ readers and dashboards.** Choose repository names, register organ
   identities, implement the registries and versioned readers, and add one lens
   adopter plus fixtures for multiple independent producers. Keep rendered output
   reproducible from captured inputs; it must work without scientific imports.
3. **Onboard a second real project in each domain.** Demonstrate different project
   conventions behind the same domain contract. Only then declare cross-project
   support complete. Register cockpit feeds and transition the existing profiling
   card; retain project dashboards and result ownership.

These are candidate implementation tasks, not newly filed work or authorization
to create repositories. Organ names and actual second adopters remain open choices;
those choices do not prevent defining the contracts now. No shared framework is
needed before two concrete exporters/readers demonstrate reusable code.

Acceptance cases for implementation: valid empty producer; one project unavailable;
unsupported schema; duplicate record ID; stale cached snapshot; unknown provenance;
compile/runtime mismatch; changed hardware; changed scientific target; missing
convergence evidence; failed inference seed; partial pipeline; and unavailable
sample archive. A second producer must register without changing the reader's
project-specific branching. Displayed values must trace to a captured source;
no test may require production HPC runs or changes to scientific conclusions.

## Implementation reconciliation — 4 October 2026

The human selected **PyAutoInsight**, key `insight`, for inference. The 2–3
October Pulse campaign control room supersedes the evidence-only intent split
in this original proposal: Pulse and Insight own their domain campaign intent
and pending tasks. Mind retains bounded implementation PR lifecycle and claims;
Cortex retains authoritative scientific run records, observations and human
conclusions. Project producers and execution drivers remain project-owned.
Insight follows this boundary with no new conductor and no revival of the
retired inference programme. See [Insight](../organs/insight.md).
